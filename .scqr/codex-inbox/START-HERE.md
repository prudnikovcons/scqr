## Стиль SCQR (закон для всей графики)

**Среда:**
- Лиловый фоновый градиент `#F1ECFF → #E9E2FF`. Иногда тёплый край `#FFF8E8`.
- Photographic 3D-рендер с soft studio lighting, лёгкий depth-of-field, лёгкая лиловая дымка для глубины.

**Палитра объектов:**
- `#17142E` — тёмный navy для тяжёлых элементов (серверы, плиты)
- `#7C5CFF` — фиолетовый для акцентной подсветки
- `#A3E635` — лайм-сигнал, **ТОЛЬКО** для линий, стрелок, контрольных точек, не как заливка фона
- Белый/слоновая кость — карточки и маскот
- Красный `#F23B3B` — только в очках маскота

**Шрифты на обложках:** Inter / system-ui sans-serif. Заголовок weight 700 тёмно-navy. Подзаголовок weight 500 муть-лиловый `#5C5685`.

**Маскот SCQR (когда задание это требует):**
- Анатомия 3D — белый/слоновая кость корпус, лёгкое студийное освещение.
- **ОБЯЗАТЕЛЬНО красные прямоугольные очки** с закруглёнными углами `#F23B3B`. Без них это не наш маскот.
- Зрачки фиолетовые с лаймовой точкой по центру.
- Тёмно-navy конечности.
- Если в задании указан путь к референсу — открой его, выровняй пропорции под него.

**Универсальные ограничения:**
- НИКОГДА не используй логотипы реальных компаний (NVIDIA, OpenAI, Anthropic, AWS, Google, Meta).
- НИКОГДА не пиши большие надписи AI / GPT / Future / Innovation в кадре.
- Не ставь чёрные тени-прямоугольники, не оставляй шахматный фон, не сваливай в фоторежим NVIDIA-промо со студийным железом.
- Главный объект — в центральных 60% по горизонтали, чтобы при кропе до 4:3 в карточках архива смысл не обрезался.
- Маленькое лого SCQR в правом верхнем углу: фиолетовый круг с одной лаймовой точкой, ~60×60 px area.
- Тонкая лаймовая линия по нижней кромке (5% высоты).

## Что делать после генерации

1. Сохрани PNG **строго по абсолютному пути** из `target_path`. Если папок нет — создай. Размер 1536×1024 PNG sRGB.
2. Файл задания (`.md`) **не редактируй** и **не двигай**. Наш watcher (review-server) сам увидит появление PNG по target_path и переместит задание в `codex-done/`, обновит статус, для type=cover автоматически подвяжет обложку к статье.
3. Переходи к следующему `pending`-заданию.

---

## Если задание не выходит

После двух попыток с разным seed — отметь его failed и пропусти:

1. Открой файл задания, в frontmatter измени `status: pending` на `status: failed`, добавь строку `error: <короткая причина>`.
2. Тело не трогай.
3. Переходи к следующему.

## Что НЕ делать

- Не редактируй файлы вне `codex-inbox/`. Не трогай статьи в `site/src/content/posts/`.
- Не запускай `git`, `pnpm build`, `pnpm review`. Никаких системных команд.
- Не правь sidecars, не меняй frontmatter статей, не трогай Astro-компоненты.
- Не читай `codex-done/` (там старые задачи, они уже выполнены).
- Не задавай вопросов, не пиши комментарии в файлы заданий, кроме `error:` в случае provala.
